## Summary

Scale run over a 30032-node fleet (30000 simulated / KWOK, 29548 Ready) exercising: node scaling (P0.2); fault→cordon→drain→GPUReset remediation (P0.4). Records control-plane latency/throughput, remediation latency, component CPU/memory, and a harness-vs-real ceiling attribution so the binding constraint for Phase 2 is explicit.

## Motivation

Phase 2 (full-system scale) needs a defensible node/cluster ceiling and a way to separate test-harness cost from real cluster cost. Node-scaling cost is driven by:

- Served/cached Node object count → API server LIST response size + duration (etcd range reads)
- Node heartbeat-lease churn → API server write/watch traffic
- kwok-controller capacity to keep every simulated node's lease fresh (the harness limit)
- client-go QPS/burst throttling on the scale-up path
- Remediation throughput (fault→cordon→drain→GPUReset) under a large fleet

We need current-release baselines, configuration guardrails, and an explicit statement of which resource is the binding constraint.

## Measurement validity

- Stable object IDs: simulated nodes have deterministic names (`kwok-gpu-<n>`); injected events carry a per-event correlation id
- Warmup / window: Prometheus peaks taken as `max_over_time` over a 6h window; ceiling rungs settle before sampling
- Hard timeout: node-readiness is capped per rung (`NODE_READY_TIMEOUT`) so a rung terminates instead of hanging
- Harness vs real saturation is distinguished (kwok-controller vs apiserver/etcd) — see Pass criteria → At saturation
- Live state: node/cordon/CR/Job counts come from an authoritative LIST at report time, not cached
- ⚠️ Single run on a possibly-shared cluster; absolute latencies include background load — prefer the trend over any single value. The sibling specs call for ≥3 repetitions on a quiet cluster

## Pass criteria

**At expected peak:**

- ✅ apiserver all-verb p99 0.395s within guardrail 1.00s
- ⚠️ apiserver 5xx rate peaked at 551.00/s (shared-cluster background if not test-attributable)
- ⚠️ KWOK node readiness 98.5% (<99%) — kwok-controller heartbeat ceiling

**At saturation:**

- Limiting resource: REAL ceiling: apiserver LIST-nodes p99 29.678s exceeded guardrail 1.000s — large-collection LIST against apiserver/etcd is the bound for node scale (Phase 2). Overall read p99 stays low (0.753s) and in-flight peak 73, so it's LIST-fanout cost, not general control-plane saturation.
- Degradation is observable via the per-rung LIST-nodes p99 curve and the node-readiness fraction
